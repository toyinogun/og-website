# worker/

The site's one Worker script, for the contact form (spec [0006](../docs/specs/0006-contact-form/index.md)). Cloudflare runs it only for `/api/*` (`assets.run_worker_first` in `../wrangler.jsonc`); every page, image and unknown path stays a free static asset (spec 0001).

## Files

- `index.ts`: the edge. The only file that touches the real `fetch`, clock, `console`, `crypto` and the Healthchecks.io alarm; it wires them into the handlers as `deps`.
- `contact.ts`: `POST /api/contact` (`handleContact`). Every way a request ends is one row of `EXITS` (the spec's *Exit table*), turned into the JSON response, the one log line and the alarm in one place.
- `turnstile.ts`: `verifyTurnstile`, the siteverify call, with `fetch` passed in.
- `weekly.ts`: `handleScheduled`, the Monday 08:00 UTC self check (AC-21).
- `worker-configuration.d.ts`: generated by `npx wrangler types worker/worker-configuration.d.ts`; never edit it by hand. CI fails when it drifts from `wrangler.jsonc`, so regenerate it after any binding, var or secret change.
- `tsconfig.json`: types the Worker with the Workers runtime types, apart from the site's Astro and Node types (the root `tsconfig.json` excludes `worker/`). `npm run check` and `npm run build` run it as `tsc -p worker`.

## Rules

- The words, limits, validation and email text live in `../src/lib/contact.ts`, shared with the browser so both judge a message the same way. Never copy them here.
- Handlers take every outside effect through `deps` (`ContactDeps`, `WeeklyDeps`) and the bindings through `env`, so tests pass fakes. Only `index.ts` builds the real ones.
- A new way for a request to end is a new `EXITS` row, never an ad hoc `Response`.
- Save the KV copy before sending the email, and never retry the email. Two writes to one outbox key stay `SAME_KEY_GAP_MS` apart (KV allows one write a second per key).
- Log lines carry no name, email, message text or IP address.
- Secrets (`CONTACT_TO`, `TURNSTILE_SECRET_KEY`, `HEALTHCHECK_URL`) are set with `npx wrangler secret put <name>` and listed under `secrets.required` in `wrangler.jsonc`; never write their values in the repository. The inbox address appears only as `you@example.com`.

## Tests and local proof

- Tests sit beside each file as `*.test.ts` and run in `npm test` (`vitest.config.ts` includes `worker/**/*.test.ts`), with fake bindings and a fixed clock.
- Local run: copy `../.dev.vars.example` to `.dev.vars` (never committed), then `npm run build:local && npx wrangler dev --test-scheduled`, and open `http://localhost:8787/contact`. The steps to check are in `../docs/specs/0006-contact-form/verify.md`.
